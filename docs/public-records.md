# 官方公开数据源清单：用"人名 → 地址"锚定身份

> 状态：v1 草案 · 最近核对：2026-11 · 适用：中国大陆
>
> 约定：`[需实测确认]` 表示入口名称可靠、但具体地址/路径/字段名未经本文验证；`L0–L6` 为本文自定义的地址精度分级（见 §1）。所有域名只作为定位线索，不作为接口承诺——政府站点改版频繁，**以官网导航为准**。

---

## 0. 核心论点

**用官方公开源把"人名 → 地址"锚定，比泄露库更准、更稳、更能举证。**

这句话不是立场，是四个可验证的属性差异：

| 维度 | 官方公开源 | 泄露库（社工库 / 撞库库 / 内部导出） |
|---|---|---|
| **时效** | 按年报、公示、判决滚动更新，能标注观测时间 | 快照停留在泄露那一刻。多数库的主体数据是 2010 年代前期，地址早已失效 |
| **字段语义** | 有法定填报口径：谁是"住所"、谁是"送达地址"、谁是"执业机构"，定义清楚 | 无 schema。同一列混着收货地址、注册地址、单位地址，字段名还叫 `addr` |
| **可举证** | 能给出页面、发布时间、文号、案号；可以截图存档，必要时可作为线索提交 | 无法在任何正式程序中使用；**取得行为本身**就可能构成犯罪 |
| **稳定性** | 站点是政府域名，十年后大概率还在 | 站点随时关停、跑路、被查；今天的入口明天就打不开 |
| **覆盖率** | 对农村、老年、非网购人群覆盖好（村务公开、保障房、招聘公示恰好覆盖这批人） | 对上述人群覆盖极差——他们本来就不产生电商和 App 数据 |

泄露库唯一占优的地方是**一键出结果**。它把检索成本压到了零，代价是把准确性、时效和法律风险全部转嫁给你。正确做法不是二选一，而是：

> **以官方源为主干建立本地索引，把检索成本一次性摊销；泄露库不进入流程。**

---

## 1. 地址精度分级

统一用这套分级描述"这个源能到哪一层"，比"精确/不精确"有用得多：

| 级别 | 粒度 | 典型形态 | 对定位的意义 |
|---|---|---|---|
| **L0** | 无地址 | 只有法院、只有单位名 | 只能做归属判断，不能定位 |
| **L1** | 省级 / 城市 | "广东省深圳市" | 与身份证地址码同量级，信息量很低 |
| **L2** | 区县级 | "北京市朝阳区" | 十万–百万人量级，仍不构成定位 |
| **L3** | 街道 / 乡镇 | "××街道" | 万人量级 |
| **L4** | 社区 / 村 / 村民组 | "××村×组" | 千人量级，农村场景的实际落脚点 |
| **L5** | 门牌 / 楼栋 | "××路××号×栋" | 百人量级 |
| **L6** | 房号 | "×栋×单元×××室" | 个位数人量级 |

一条经验规则：**L4 以下（含）不足以指认个人，L5 以上才谈得上"地址"**。很多"身份证解析"输出到 L2 就被当成住址使用，这是把行政区划误当成了居住地。

---

## 2. 方法论：五步收敛

不要指望单一源给全。标准流程是把不同精度的源串起来，逐步收窄：

```
第 1 步  消歧        姓名 + 出生年月（或身份证打码段）→ 锁定唯一自然人
第 2 步  挂靠        姓名 → 企业（法定代表人/股东）→ 统一社会信用代码
第 3 步  落地        企业 → 住所 / 宗地 / 中标项目 / 专利申请人地址
第 4 步  校准        司法文书"住所地"、招聘公示"报考单位"、保障房"小区房号"
第 5 步  定级        两条以上独立源指向同一 L5 且时间差 < 3 年 → 可采信
```

三条硬规则：

1. **先消歧，再找地址**。跳过第 1 步直接按姓名搜地址，得到的必然是重名混合体。
2. **每条地址必须带观测时间**。地址会变；没有时间的地址等于没有地址。
3. **精度不对齐时以低精度为准**。一个源说 L2、一个源说 L6，不能直接认为"确认到房号"，要检查两者是否指向同一行政区。

## 3. 源清单（按可获取字段组织）

### 3.1 司法

#### 中国裁判文书网

- **入口**　最高人民法院 中国裁判文书网（`wenshu.court.gov.cn`，`[需实测确认]`）
- **可获取字段**　案号、法院、案由、审理程序、裁判日期、当事人（自然人常隐名）、委托诉讼代理人、诉讼请求、查明事实、判决主文、审判人员
- **地址精度**　L2–L4 为主（"住××省××市××区"），少数到 L5（"××路××号××小区×栋"）。2010 年代中期后隐名化加强，地址常被删减到区县
- **反爬与访问限制**　需登录（手机号验证）；图形/行为验证码；检索频次与翻页限制；热点案由限流
- **API / 批量**　无公开 API，无官方批量下载通道
- **常见打码与失效**　自然人姓名打码为"张*""张某"；身份证号打码；大量文书标记"不予公开""撤回"；同一案号在不同时间检索结果可能不一致；文书上网率逐年下降，**早年案件覆盖反而好于近年**
- **用法**　用"当事人 + 案由 + 地域"组合检索；把"住址"理解为**送达地址**（当事人自己填的），不等于实际居住地；用案号做唯一键去重

#### 中国执行信息公开网

- **入口**　最高人民法院 中国执行信息公开网（`zxgk.court.gov.cn`，`[需实测确认]`）
- **栏目**　被执行人、失信被执行人、限制消费人员、终本案件
- **可获取字段**　姓名/名称、身份证号（**部分打码**，形如 `110101********1234`）、执行法院、案号、立案时间、执行标的、失信情形、发布时间
- **地址精度**　L0——**没有任何住址**，只有执行法院
- **反爬与访问限制**　图形验证码；查询频次限制；无需登录
- **API / 批量**　无公开 API
- **常见打码与失效**　履行完毕或达成和解后屏蔽/删除；名单更新有滞后；同名多行需逐条比对身份证尾号
- **用法**　这不是地址源，是**消歧源**。打码身份证的前 6 位是地址码、后 4 位可与已知号码对齐，"姓名 + 出生段 + 尾号"三者交叉，重名问题基本解决

#### 人民法院公告网 / 司法拍卖

- **入口**　人民法院公告网（`[需实测确认]`）；阿里司法拍卖、京东司法拍卖的法院专场
- **可获取字段**　公告类型（起诉状副本送达、开庭、执行、破产）、当事人、公告法院、公告日期；拍卖标的物**坐落（常到门牌/房号）**、评估价、起拍价、权利人姓名
- **地址精度**　拍卖公告 L5–L6；送达公告 L2–L4
- **反爬与访问限制**　低–中
- **API / 批量**　无
- **常见打码与失效**　公告有期限，过期下线；拍卖页在成交后保留一段时间后撤除
- **用法**　"下落不明"的送达公告常附原户籍地址；拍卖公告是少数**公开到房号**的源

### 3.2 企业

#### 国家企业信用信息公示系统

- **入口**　国家市场监督管理总局（`gsxt.gov.cn`，`[需实测确认]`）
- **可获取字段**　名称、统一社会信用代码、类型、**法定代表人**、注册资本、成立日期、营业期限、登记机关、核准日期、**住所**、经营范围、**股东及出资**、主要人员、分支机构、**变更记录（含历次住所）**、年报（企业联系电话、邮箱、网址、从业人数、资产状况，企业可选择不公示）、行政处罚、经营异常、严重违法失信、股权出质、动产抵押、司法协助（股权冻结）
- **地址精度**　L5（住所常到"××路××号×栋×室"）
- **反爬与访问限制**　**极强**。滑块 + 点选 + 行为验证码；IP 频次限制；部分省份跳转地方站，页面结构随省份变化
- **API / 批量**　无公开 API。数据共享接口需通过省级市场监管部门申请 `[需实测确认]`
- **常见打码与失效**　年报数据由企业自行填报，真实性不保证；**集群注册/托管地址**（同一地址挂几百家企业）会让"地址→人"完全失效；注销企业仍可查，但住所停留在注销时
- **用法**　"人名 → 企业 → 住所"的**主干源**。用法定代表人/股东检索同名时，需要出生年月或身份证尾号消歧——公示系统本身不显示身份证号

#### 信用中国 / 地方信用网

- **入口**　信用中国及各省市信用门户（`[需实测确认]`）
- **可获取字段**　行政许可、行政处罚、红黑名单、重大税收违法失信主体、失信被执行人（转发）
- **地址精度**　行政处罚决定书常含当事人地址，L4–L5
- **反爬与访问限制**　中等；部分站点设"数据开放"栏目提供数据集下载 `[需实测确认]`
- **API / 批量**　部分省市提供开放数据接口 `[需实测确认]`
- **常见打码与失效**　处罚公示有期限（一般 1–5 年），过期撤下
- **用法**　**高价值、低竞争**的源，普遍被忽略。处罚决定书里"当事人住所"写得很实

### 3.3 不动产与土地

#### 不动产登记

- **入口**　各地不动产登记中心 / 自然资源局（无全国统一的对外查询入口）
- **关键事实**　《不动产登记暂行条例》第 27–28 条把查询主体限定为**权利人和利害关系人**，"以人查房"不对社会开放。任何声称"输入姓名查全国房产"的服务，都不是官方通道
- **公开可得的只有程序性信息**　登记结果公告、遗失声明、继承/受遗赠公告、查封公告、司法拍卖
- **可获取字段**　权利人（公告中常隐名）、坐落（**常到门牌/房号**）、面积、用途、权利类型
- **地址精度**　L5–L6
- **反爬与访问限制**　各市独立站点，多为静态页或 PDF
- **API / 批量**　无
- **常见打码与失效**　公告期结束即撤；权利人姓名常隐去姓氏之外的字
- **用法**　只在"已进入公示程序"的场景可用，不能当常规查询手段

#### 土地出让（中国土地市场网）

- **入口**　自然资源部 中国土地市场网（`landchina.com`，`[需实测确认]`）
- **可获取字段**　宗地编号、**宗地坐落**、面积、用途、出让年限、供地方式、**受让人**、成交价、签订日期、约定开工/竣工、容积率
- **地址精度**　L4–L5（地块坐落，不一定是门牌号）
- **反爬与访问限制**　中等；页面走异步查询，参数需实测
- **API / 批量**　无文档化公开 API
- **常见打码与失效**　早期数据缺失；划拨用地公示不全；受让人常是项目公司而非自然人
- **用法**　"企业 → 地块 → 地址"。配合 gsxt 做股东穿透，能把"某公司在某地有地"落到具体宗地

### 3.4 招投标

#### 全国公共资源交易平台 + 省市子站

- **入口**　全国公共资源交易平台（`ggzy.gov.cn`，省级子站各自独立，`[需实测确认]`）
- **可获取字段**　招标公告、中标候选人公示、中标结果、合同公示；招标人、代理机构、**中标人**、中标金额、**项目负责人**（部分含执业证书编号）、项目地点
- **地址精度**　L3–L5（工程类常到具体路段/地块）
- **反爬与访问限制**　各站不一，多数是静态 HTML/JSON；部分需 CA 证书才能看完整文件
- **API / 批量**　部分省市有开放数据接口 `[需实测确认]`
- **常见打码与失效**　公示期结束即下线；关键信息藏在 PDF 附件里，需 OCR
- **用法**　"人 → 企业 → 项目地址"；项目负责人字段能确认"此人在此时间段属于此公司"，是很强的时间锚点

### 3.5 知识产权

#### 专利（国家知识产权局）

- **入口**　专利检索及分析系统、专利公布公告（`cnipa.gov.cn` 体系，`[需实测确认]`）
- **可获取字段**　申请号、公开号、申请日、**申请人（自然人真实姓名）**、发明人、**申请人地址（常到门牌）**、代理机构、摘要、权利要求
- **地址精度**　L5
- **反爬与访问限制**　需注册登录；下载有配额；验证码
- **API / 批量**　无免费公开 API；商业库（incoPat、智慧芽等）有，需付费
- **常见打码与失效**　申请后 18 个月内未公开的查不到；地址是申请时填的**通信地址**，可能过期；注意区分"申请人地址"与"代理机构地址"
- **用法**　**被严重低估的源**。个人申请的专利，申请人地址经常精确到门牌，且与姓名强绑定，几乎没有重名干扰

#### 著作权登记

- **入口**　中国版权保护中心（`ccopyright.com.cn`，`[需实测确认]`）
- **可获取字段**　登记号、作品/软件名称、**著作权人**、开发完成日期、首次发表日期、登记日期
- **地址精度**　L0–L1（一般不含地址）
- **反爬与访问限制**　中等，有验证码
- **API / 批量**　无
- **常见打码与失效**　只公示已登记且同意公开的部分
- **用法**　只做"人名 → 作品/公司"的关联确认，不用来找地址

### 3.6 学术

#### 学位论文

- **入口**　各高校图书馆 / 机构知识库；国家科技图书文献中心；商业库 CNKI、万方
- **可获取字段**　作者、导师、学校、院系、专业、年份、题名、关键词、摘要、参考文献
- **地址精度**　L1（学校所在城市）
- **反爬与访问限制**　高校库多限校内 IP；商业库需订阅
- **API / 批量**　商业库有，受订阅协议约束
- **常见打码与失效**　涉密论文不公开；部分学校只公开题录不公开全文
- **用法**　"姓名 + 学校 + 年份 + 专业"是四元消歧，对同名极其有效；致谢里偶有工作单位信息

#### 基金项目

- **入口**　国家自然科学基金 科学基金共享服务网；国家社会科学基金项目数据库（`[需实测确认]`）
- **可获取字段**　项目名称、**负责人**、**依托单位**、批准号、资助金额、起止年月、摘要、结题成果
- **地址精度**　L1（依托单位所在城市）
- **反爬与访问限制**　低–中
- **API / 批量**　无公开 API
- **常见打码与失效**　只覆盖已结题/已公开项目；在研项目信息可能滞后
- **用法**　"人名 → 单位 → 时间段"，是很好的时间锚点：某人在某几年挂在某单位

### 3.7 人事公示

#### 事业单位招聘 / 公务员录用公示

- **入口**　各地人社局、教育局、卫健委官网的"拟聘用人员公示"栏目（高度分散，无统一入口）
- **可获取字段**　姓名、性别、**出生年月**、学历学位、**毕业院校**、专业、**准考证号**、报考单位、岗位、笔试/面试成绩、体检结论
- **地址精度**　L1–L2（单位地址）
- **反爬与访问限制**　低，多为静态 HTML 或 Excel/PDF 附件
- **API / 批量**　无
- **常见打码与失效**　**公示期通常 5–7 天，过期即删**；必须靠存档/网页快照
- **用法**　"姓名 + 出生年月 + 毕业院校"是公开源里最强的消歧三元组之一；准考证号可跨场次关联同一人

### 3.8 住房保障

#### 保障房分配公示

- **入口**　各市住建局 / 住房保障中心的"保障性住房分配结果""公租房摇号结果"（分散）
- **可获取字段**　姓名、身份证号（打码）、家庭人口、**街道/社区**、**小区名称**、**房号**、面积、租金档位
- **地址精度**　L4–L6
- **反爬与访问限制**　低
- **API / 批量**　无
- **常见打码与失效**　公示期短；部分只发 PDF 扫描件；老小区可能已更名
- **用法**　少数能公开到"小区 + 房号"的源，但仅限已获保障资格的家庭，覆盖率天然很低

### 3.9 基层政务

#### 干部任前公示

- **入口**　县/区政府网站、组织部公示栏
- **可获取字段**　姓名、性别、**出生年月**、**籍贯**、党派、参加工作时间、学历、现任职务、拟任职务
- **地址精度**　L1–L2
- **反爬与访问限制**　低
- **API / 批量**　无
- **常见打码与失效**　公示期短；县级站点改版频繁
- **用法**　**籍贯字段**是官方文件里少见的显式地域信息，可与身份证地址码交叉验证

#### 村务公开 / 惠农补贴 / 低保公示

- **入口**　乡镇政府网站、村务公开栏、"三务公开"平台、县政府信息公开专栏
- **可获取字段**　姓名、**村/村民组**、补贴类型、金额、发放时间；村干部名单及职务
- **地址精度**　L4–L5
- **反爬与访问限制**　低，但站点极度分散，大量 PDF/图片/表格
- **API / 批量**　无
- **常见打码与失效**　县级政府网站改版/关停导致链接失效，必须自行存档
- **用法**　**农村地址锚定的关键源**。泄露库对农村老年群体覆盖极差，这里恰好补上

### 3.10 执业注册（加分源）

这类库的共同点：**姓名 + 单位 + 证书编号**，证书编号是天然唯一键，消歧成本接近零。

| 源 | 可获取字段 | 精度 |
|---|---|---|
| 住建部 全国建筑市场监管公共服务平台（"四库一平台"） | 注册建造师/监理工程师姓名、注册单位、证书编号、注册专业 | L1–L2 |
| 国家卫健委 医师执业注册信息查询 | 姓名、执业机构、执业范围、证书编码 | L1–L2 |
| 司法部 律师/律所查询 | 姓名、执业机构、执业证号 | L1–L2 |
| 财政部 注册会计师查询 | 姓名、事务所、证书编号 | L1–L2 |
| 证监会 行政处罚 / 市场禁入 | 姓名、职务、违法事实、处罚结果 | L0–L1 |
| 税务总局 重大税收违法失信主体 | 企业名称、法定代表人、负有直接责任的财务人员 | L1–L2 |
| 民政部 社会组织 / 基金会查询 | 名称、法定代表人、**住所**、业务范围 | L4–L5 |

## 4. 组合打法

不同目标的最短路径（箭号表示"由前一列推导后一列"）：

| 目标 | 首选 | 次选 | 收敛条件 |
|---|---|---|---|
| 自然人的**登记地址** | gsxt（法定代表人/股东） | 信用中国处罚决定书 | 两个源的企业住所一致 |
| 自然人的**居住地址** | 保障房公示 | 村务/低保公示 | 同街道 + 同小区/村组 |
| 自然人的**通信地址** | 专利申请人地址 | 招投标项目负责人 | 地址与单位所在地同城 |
| 自然人的**送达地址** | 裁判文书"住所地" | 人民法院公告网送达公告 | 案号时间与其它源相差 < 3 年 |
| 企业 → **地块** | 中国土地市场网 | 招投标中标公示 | 受让人 = 中标人 |
| 同名消歧 | 招聘公示（出生年月+院校） | 执行公开网（打码身份证） | 出生年月 + 尾号 双匹配 |

一条可直接实现的置信度规则：

```
confidence = high    若 ≥2 个独立源 → 同一 L5 以上 且 时间差 < 3 年
confidence = medium  若 ≥2 个独立源 → 同一 L4，或 L5 但时间差 3–5 年
confidence = low     其余
```

## 5. 失效与噪声（必须写进 caveat）

| 噪声类型 | 表现 | 处理 |
|---|---|---|
| **地址语义漂移** | 登记地址 / 送达地址 / 通信地址 / 居住地址 是四个不同概念 | 每个地址标注"语义类型"，不混用 |
| **集群注册** | 一个地址挂几百家企业 | 该地址的"地址→人"权重降为零 |
| **企业注销/迁址** | 住所停留在注销时 | 用"变更记录"取时间序列 |
| **隐名化** | "张某""张*"，地址被删减 | 转为消歧线索，不作地址依据 |
| **重名** | 同名不同人，尤其中性名 | 必须走 §4 的消歧列 |
| **数据滞后** | 年报、判决、公示都有 3–18 个月延迟 | 记录 `observed_at`，不用"当前"表述 |
| **站点消失** | 县级站点改版、栏目下线 | 抓取即存档（HTML + PDF + hash） |
| **OCR 错误** | 扫描件里的门牌号识别错 | 关键字段双人复核或换源比对 |

## 6. 法律性质分级（如实写）

| 级别 | 性质 | 典型源 | 使用边界 |
|---|---|---|---|
| **A** | 法定主动公开 | 企业登记公示、应公开的裁判文书、事业单位招聘公示、村务公开、土地出让公告、行政处罚公示 | 可检索、可引用、可存档。仍受《个人信息保护法》第 27 条约束：**已公开的信息也必须在合理范围内处理** |
| **B** | 依申请 / 特定资格查询 | 不动产登记、户籍、婚姻登记、学籍、征信 | 仅权利人、利害关系人、司法机关；**没有"公开渠道"这回事** |
| **C** | 商业数据库 | CNKI、incoPat、企查查类 | 受订阅协议约束；转售、批量外供通常违约甚至违法 |
| **D** | 泄露数据检索 | 社工库、"查档""开盒""人肉"服务、内部人员导出 | **非法获取**。《刑法》第 253 条之一"侵犯公民个人信息罪"，司法解释对"情节严重"有明确数量门槛；买卖同罪，"只查不传"也可能构成非法获取 |

补充三条事实，不做修饰：

1. 公开裁判文书中可以检索到多起**运营"社工库"查询服务牟利**被以侵犯公民个人信息罪定罪的判例。具体案号请在裁判文书网自行核实——本文不引用无法验证的案号。
2. 裁判文书公开本身也长期存在个人信息保护争议，这与大量文书做隐名化处理、上网率下降的现象直接相关。
3. A 类信息**不等于可以随意聚合**。把分散的公开信息拼成一份"个人档案"再传播，性质会变——《个人信息保护法》第 27 条要求处理已公开个人信息"在合理的范围内"，并对个人权益有重大影响的处理需取得同意。

## 7. 本清单不做的事

- 不提供任何泄露库、社工库、撞库数据的入口、检索方法或"替代关键词"。
- 不提供绕过验证码、破解登录、伪造身份以通过实名认证的方法。
- 不把 A 类公开信息加工成可直接指认个人的档案并对外分发。

原因不是姿态：前两项落在上表的 D 级（《刑法》第 253 条之一），第三项是 A 类信息的越界聚合（《个人信息保护法》第 27 条）。

## 8. 落地建议：把检索成本摊销一次

这套源真正的瓶颈不是"能不能查到"，而是"每次都要重查一遍"。可行做法：

1. **本地索引**　SQLite 或 Parquet，字段固定为 `entity / field / value / source / url / observed_at / confidence`。
2. **抓取即存档**　公示期只有几天，抓到立刻存 HTML + PDF，算 SHA-256，链接失效后仍可回溯。
3. **唯一键去重**　统一社会信用代码、案号、证书编号、登记号——有就用，不要用姓名做键。
4. **季度滚动**　A 类源按季度增量更新；B 类源永不进入自动流程。
5. **可审计**　每条记录保留原始 URL 与观测时间，任何人可以复核到你看到的那一页。

做到这五点，"人名 → 地址"就从一个每次都要现场搜索的动作，变成一次查询本地库的动作——**这才是官方源相对泄露库真正的成本优势**。
